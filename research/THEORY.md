# THEORY.md — In-context examples and covariates in iAmTime forecasting

Authoritative statement of the problem, the results established so far, and the experiments that should be run next. The reader is assumed to have the repository and no other context. Do not edit this file from an experiment session: record outcomes in `research/FINDINGS.md` (template there), tagging each entry CONFIRMS / REFINES / CONTRADICTS a numbered result below.

---

## 1. Problem statement, notation, assumptions

### 1.1 The question

iAmTime is a time-series foundation model whose input is an *episode*: a set of completed support examples (history → future, optionally with covariates) followed by a query whose future is to be predicted, all in one forward pass and without parameter updates. The released checkpoint is forecasting-only. The research question of this programme is:

> **Under what conditions do in-context examples and covariates improve iAmTime's forecasts, by how much, through which mechanism, and where do they fail?**

Five demonstration notebooks on public data (fev-bench retail, energy, economics; an assembled S&P 500 finance set) are the prototype evidence. This document turns their results into numbered, falsifiable statements.

### 1.2 Objects

| Symbol | Meaning |
|---|---|
| $y_{1:T}$ | a univariate target series; the forecast origin is index $T$ (exclusive) |
| $L$ | query context length: the model sees $x_q^{\mathrm{hist}} = y_{T-L+1:T}$ |
| $H$ | forecast horizon; ground truth $y_{T+1:T+H}$ is held out |
| $z^{\mathrm{hist}} \in \mathbb{R}^{M\times L}$, $z^{\mathrm{fut}} \in \mathbb{R}^{M\times H}$ | $M$ covariate series over the context and the horizon. A covariate is **known-future** if $z^{\mathrm{fut}}$ is available at $T$ (calendars, planned promotions, published day-ahead forecasts) and **past-only** if only $z^{\mathrm{hist}}$ is (VIX, commodity prices, other variates of a multivariate target) |
| $E_i = (x_i^{\mathrm{hist}}, z_i^{\mathrm{hist}}, x_i^{\mathrm{fut}}, z_i^{\mathrm{fut}})$ | support example $i$: a completed window of length $L_e + H_e$ taken from any series, ending **before** $T$ |
| $S = \{E_1,\dots,E_k\}$ | the example set; $k$ = number of examples ($k=0$ is plain zero-shot) |
| $Q = (x_q^{\mathrm{hist}}, z_q^{\mathrm{hist}}, z_q^{\mathrm{fut}})$ | the query |
| $f_\theta(Q \mid S)$ | the model's output: quantiles $\hat q_\tau(h)$, $\tau \in \{0.1, 0.5, 0.9\}$, $h = 1..H$; $\hat y = \hat q_{0.5}$ is the point forecast |
| $\sigma$ | a **selection operator** mapping a query to an example set, $S = \sigma(Q, \mathcal{D}_{<T})$, using only data before $T$ |
| $\pi$ | a **control** that keeps the amount of data but breaks the demonstrated pairing: *shuffled futures* rotates $x_i^{\mathrm{fut}}$ across the examples so no history is paired with its own future |

Model-side facts the theory relies on (from `src/iAmTime/`):

- **Tensor contract** (`model.py: iAmTimeModel.forward`, `pipeline.py: icl_input_attributes`): `example_target_histories (B,E,L_e)`, `example_target_futures (B,E,H_e)`, `example_exog_histories (B,E,M,L_e)`, `example_exog_futures (B,E,M,H_e)`, `query_target_history (B,L)`, `query_exog_history (B,M,L)`, `query_exog_future (B,M,H)`. Covariates are positional, not named: row $m$ must be the same covariate in every block.
- **Per-series instance normalisation** (`model.py: _patch_and_embed`, `layers.py: InstanceNorm`): every series in a block, target and each covariate, is normalised by the mean and RMS of its *own history*; futures reuse the history's `loc_scale`. A zero-variance history gives `scale = eps = 1e-5` (then `arcsinh` if `iamtime_config.use_arcsinh`).
- **Multivariate is not native** (`pipeline.py: _expand_multivariate`): a `(variates, L)` target becomes `n_variates` univariate items, each with the other variates appended as **past-only** covariates (`query_exog_future` empty). Hence every multivariate result below is a past-only-covariate result.
- **Retrieval path** (`blocks.py: token_slots, build_allow_patchsplit; CompositeICLEncoderBlock`): the query's `START` and `MID` tokens cross-attend to the examples' tokens; the example `START` token reads the example's entire window *including its target future*; the decoder consumes only the query's future-target patches plus `START` and `MID`. This is the only channel through which example futures reach the query forecast.
- Trained with up to 6 examples; the pipeline accepts any $k$.

### 1.3 Evaluation protocol (fixed across all results)

- **MASE** per series: $\mathrm{MASE} = \dfrac{\frac1H\sum_{h=1}^{H}|y_{T+h}-\hat y_{T+h}|}{\frac{1}{L-m}\sum_{t=T-L+1+m}^{T}|y_t-y_{t-m}|}$ with the seasonal lag $m$ of the data (1 for weekly Walmart and monthly/quarterly macro, 7 for daily, 24 for hourly). The denominator is an in-sample one-step *scale*, not a competing forecast; MASE > 1 does not mean "worse than naive over the horizon". Baselines are always scored on the same holdout.
- **Scorecard**: $N$ (series, origin) pairs, reporting mean and median MASE, the **win rate** $w = \Pr[\mathrm{MASE}_{\text{variant}} < \mathrm{MASE}_{\text{ref}}]$, and the paired bootstrap 95 % CI of the mean difference $\Delta$. A gain is "reliable" when the CI excludes 0.
- **Relative gain** $g = 1 - \overline{\mathrm{MASE}}_{\text{variant}}/\overline{\mathrm{MASE}}_{\text{ref}}$; a percentage below always refers to $g$ on the mean.
- **Scenario uplift** for covariate value $s$: $U(s) = \overline{\hat y^{(s)} - \hat y^{(0)}}$ over the event window, where $\hat y^{(0)}$ is the forecast with the event removed and everything else identical.

### 1.4 Assumptions

A1. The checkpoint `anishsaha/iAmTime-base-forecast` is fixed; no fine-tuning anywhere.
A2. Every example window ends at or before $T$ (no leakage); selection $\sigma$ uses only $\mathcal{D}_{<T}$.
A3. Example futures are scored-free demonstrations: the model never sees $y_{T+1:T+H}$.
A4. $L_e = L$ in all cold-start experiments (example histories as long as the query's); elsewhere $L_e = L$ too unless stated.
A5. Inference on CPU in float32; results are deterministic given seeds.
A6. Covariates are **not** passed inside examples in any FINAL result (see R9).

## 2. Results

Tag: **FINAL** = replicated in ≥ 2 datasets, or a code fact; **PROVISIONAL** = one dataset or an interpretation awaiting a discriminating experiment. "Source" is the notebook section holding the numbers; all notebooks are in `notebooks/`, summary tables in `notebooks/iamtime_forecasting_findings.md`.

### R1 — FINAL. The model reads the demonstrated history → future pairing, not merely "more context".
Statement: replacing the example set $S$ by its shuffled-futures control $\pi(S)$ raises the error far above zero-shot: Walmart 2.95 vs 1.03 (reference zero-shot), ENTSO-e 6.04 vs 1.32, GDP 8.30 vs 2.79, finance 1.88 vs 1.24, finance cold-start 2.48 vs 1.39. The one exception, Rossmann Christmas (control 1.20, still better than zero-shot 1.36), is explained by every example future containing the same holiday pattern, so even mismatched pairs carry the right information.
Derivation: if the model used examples only as additional unpaired context, $f(Q\mid S)$ and $f(Q\mid\pi(S))$ would have the same distribution of errors, since $\pi$ preserves every marginal. The observed 1.5–6× degradation rejects that, and the Rossmann exception is exactly the case where $\pi$ preserves the relevant joint (all futures alike).
Source: `iamtime_walmart_forecasting_demo.ipynb` §4f, `iamtime_energy_forecasting_demo.ipynb` §4c, `iamtime_econ_forecasting_demo.ipynb` §4c, `iamtime_rossmann_forecasting_demo.ipynb` §4c–4d, `iamtime_finance_forecasting_demo.ipynb` §4c–4d.
Corollary (FINAL): wrong examples are not neutral. ICL is only safe behind a selector that is right most of the time.

### R2 — FINAL. Examples help exactly when the horizon contains structure the query context cannot show (the redundancy principle).
Statement: the ICL gain $g$ is large when $L$ is too short to contain the seasonal or event structure that the horizon will exhibit, and vanishes when the context already contains it.
Evidence: Rossmann Christmas with $L=56$ d: $g=25\%$ (1.02 vs 1.36, $w=99\%$); the same construction year-round: $g\approx0$ (0.73 vs 0.71, CI includes 0), own-year-only slightly worse. ENTSO-e $L=56$ d with own earlier years: $g=20\%$. Walmart $L=52$ w siblings: $g=12\%$; Walmart zero-shot with $L=104$ w (0.78) beats the best $L=52$ ICL variant (0.90). Cold starts ($L$ = 12 w / 14 d / 14 d): $g$ = 20 % / 25 % / 14 % with win rates 69–90 %.
Derivation sketch: write the forecast error as $\epsilon = \epsilon_{\text{irreducible}} + \epsilon_{\text{missing structure}}$. Examples can only reduce the second term, which is bounded by the information in $y_{T+1:T+H}$ not predictable from $x_q^{\mathrm{hist}}$; when $L \ge$ one full season of a stationary seasonal process that term is small, so $g \to 0$. Prediction: $g(L)$ is monotonically non-increasing in $L$ and crosses zero near one season. (Tested in E3.)
Source: Rossmann §4c (two tables), energy §4c, Walmart §4e–4h; `iamtime_walmart_forecasting_usage.ipynb` §4e for the 104-week row.

### R3 — FINAL. Selection matters more than count; structural selectors beat similarity search.
Statement: (a) selectors that use the data's structure, own earlier years (temporal analogue), hierarchy siblings (same department / same store type / same country), and calendar alignment, give reliable gains; (b) k-means shape clustering is no better than random series (Walmart 0.992 vs 0.958, both vs 1.026); (c) k-shot curves saturate at $k \approx 3$–$5$: ENTSO-e 1.315 → 1.052 at $k=3$, flat after; GDP 2.79 → 2.49 at $k=5$, flat after; Rossmann cold start 1.23 → 0.96 at $k=1$, then slow; Walmart flat to $k=2$, 0.94 at $k=4$, 0.88 at $k=10$. Going to $k=12$ adds at most 1–3 % and never breaks the model (beyond the trained maximum of 6).
Numbers: Walmart siblings 0.904 ($w=64\%$) > season-matched 0.946 > random other-cluster 0.958 > cluster neighbours 0.992 (n.s.) > own example 1.019 (n.s.). Rossmann: own last year alone gives most of the Christmas gain (1.072 of 1.016). ENTSO-e: 3 own years 1.052; other countries only 1.114; adding 2 other countries to own years 1.047 (no further gain).
Source: Walmart §4e–4g, energy §4c–4d, econ §4c–4d, Rossmann §4c–4e, finance §4e.

### R4 — FINAL. Known-future covariates are the largest and most reliable gain; past-only covariates add little.
Statement: Rossmann calendars: 0.658 → 0.554 (open/holidays) → 0.375 (+ promotion calendar), $w=97\%$, $g=43\%$. EPF day-ahead load/generation forecasts: 0.600 → 0.504, $g=16\%$, $w=70\%$, all five markets. Finance calendar + earnings calendar: 1.036 → 0.957 ($g=8\%$), and 1.104 → 0.921 ($g=17\%$, $w=89\%$) on horizons containing an earnings reaction. Walmart's 10 observed covariates: mean 0.80 → 0.75, median unchanged (36/64). Past-only: GVAR commodity prices add nothing ($\Delta=-0.004$, CI includes 0) while their *oracle future* does (1.150 vs 1.217, $w=68\%$); finance market/macro past-only on top of calendars: 0.957 → 0.967 (no gain).
Interpretation: the model exploits a covariate chiefly through its future path; a past-only covariate's information is largely already in the target's own history.
Source: Rossmann §3a, energy §3a, finance §3a, Walmart §3a, econ §3a.

### R5 — FINAL (code fact + evidence). Multivariate input is past-only covariates in disguise, and gives no dependable gain.
Statement: `pipeline._expand_multivariate` lowers a `(variates, L)` target to one item per variate with the others as `query_exog_history` only. By R4 the expected gain is small, and it is: Walmart hand-picked correlated triples $-0.019$ (CI excludes 0, $w=65\%$); ETT 7 channels $-0.008$ (n.s.); FRED CEE $-0.19$ (n.s., $w=47\%$); finance within-ticker $-0.014$, industry/k-means/random triples $-0.006$ to $-0.008$ (all tiny, random no worse than structured); Rossmann sales + customers ($\rho=0.99$) **worse**, $+0.012$ (CI excludes 0, $w=29\%$); ETT oil temperature ($\rho\approx0$ with loads) worse.
Source: Walmart §2b, energy §2b, econ §2b, finance §2c, Rossmann §2b; code `pipeline.py` lines 154–332.

### R6 — FINAL. Scenario responses are monotone and right-signed, and sub-linear outside the historical range.
Statement: promotion dose–response on Walmart (synthetic uplift, history contains 1× only): predicted/true = 1.32, 1.02, 0.90, 0.81, 0.73, 0.67 at 0.5×, 1×, 1.5×, 2×, 2.5×, 3×. Rossmann real promotions: 1,124 vs 1,210 historical per promo day (0.93×, linear in the number of promo days). EPF merit-order: $-1.33$ vs $-2.02$ €/MWh per GW ($0.66\times$, linear over 0.5×–1.5×). Oil → inflation: positive in all four economies, magnitudes 0.1×–1.8× a pass-through regression. Finance earnings surprise → volume: concave, 0.14 at 2 % to 0.22 at 40 %.
Interpretation: the model interpolates within the covariate range seen in the context and shrinks toward it outside; absolute uplifts beyond the observed range are under-predicted by 20–33 %. Ranking of scenarios is preserved.
Source: Walmart §3b–3c, Rossmann §3c, energy §3c, econ §3c, finance §3c.

### R7 — FINAL. Zero-shot beats the domain baseline where the target has persistent structure, and ties or loses where it approaches noise.
Statement: Walmart 0.80 vs seasonal naive 0.96 ($w=84\%$); Rossmann 0.66 vs 0.79 (83 %); ERCOT 0.91 vs 1.48 (94 %); US consumption 3.93 vs random-walk-with-drift 4.23 (57 %, loses in calm years 2015/2018/2024); finance log-volume 1.04 vs 20-day mean 1.07 (tie) and realised volatility 0.84 vs 0.85 (tie); daily returns 0.773 vs zero forecast 0.769 (slightly worse, CI excludes 0).
Source: §1b of each notebook.

### R8 — PROVISIONAL. Event-aligned examples do not help single-day events on noisy targets (finance).
Statement: for log volume with a 20-day horizon containing one earnings reaction, examples aligned at the same lead give: 1 own announcement 1.353 (worse, CI excludes 0), 4 own 1.230 (n.s. vs 1.240), 2 own + 3 peers 1.296 and 5 peers 1.302 (worse), non-aligned own windows 1.348 (worse). Cold start with 5 peers: n.s. The k-curve dips at $k=1$–3 and recovers only at $k\ge4$.
Candidate explanations (to discriminate in E6): (a) a one-day spike is a small share of the 20-day MAE while the examples' idiosyncratic day-to-day noise is copied into every day of the forecast; (b) patching averages a one-day event into a patch; (c) the event's position in the example futures is aligned but its magnitude varies by 10× across announcements.
Source: finance §4c–4e.

### R9 — PROVISIONAL. Covariates inside examples suppress the query's own covariate response.
Statement: Walmart §4i: with five teacher examples carrying a `promotion` covariate (and the corresponding uplift in their futures), the query's predicted uplift at every planned strength falls to 3–5 % of the true value (zero-shot: 69–94 %). A side check found the same with a single example and with teachers showing only 1× promotions; the same teachers *without* the covariate leave the query's uplift intact. Cause unknown; A6 is the interim rule.
Hypotheses (each has an experiment in §5):
- H9a **Template copying + baseline confound.** By R1 the query forecast is pulled toward the example futures through the `START`/`MID` retrieval path. The teachers' futures all contain spikes at the *same positions* as the query's planned promotions, so the 0× baseline forecast (same examples) already contains the spikes and $U(s) = \hat y^{(s)} - \hat y^{(0)} \approx 0$ even though the raw forecast shows them. Prediction: the raw 0× forecast has spikes at the teacher positions; moving the teachers' promotions to other weeks moves the spikes.
- H9b **Covariate-channel gating.** The presence of `example_exog_*` changes `E_max`, the token layout (`token_slots`) and the allow masks (`build_allow_patchsplit`), and the trained attention may route the query's `FUT_EXOG` information differently when example `FUT_EXOG` tokens are valid. Prediction: a teacher set whose covariate is all zeros (no promotions anywhere) still kills the query's response.
- H9c **Normalisation.** Each covariate series is instance-normalised by its own history; a sparse binary covariate with few events has a small RMS and large normalised future values, and the magnitudes differ between examples and query. Prediction: the effect depends on the number of events in the example histories.
Source: Walmart §4i; code `model.py: _build_encoder_inputs`, `blocks.py: build_allow_patchsplit`, `layers.py: InstanceNorm`.

### R10 — PROVISIONAL (derived from code, untested). Sparse binary covariates with an event-free history are normalised to extreme values.
Derivation: `InstanceNorm` sets `scale = eps = 1e-5` when the history RMS is 0, so a future value of 1 becomes $10^5$ (or $\operatorname{arcsinh}(10^5)\approx 12.2$ with `use_arcsinh`). A known-future flag such as `earnings_day` or `IsHoliday` whose context window contains no event therefore enters the encoder at a magnitude never seen in training. Prediction: forecasts with such a covariate become erratic in the event patch when the context has zero events, and normal once the context contains ≥ 1 event. Relevant to every "event in horizon but not in context" use (finance §4 deliberately avoided covariates for this reason among others).
Source: `layers.py` lines 298–301, `model.py` lines 331–334.

### R11 — PROVISIONAL. The ICL gain follows a shared-signal-vs-example-noise trade-off, which explains the shape of the k-curves.
Conjecture: with templates $x_i^{\mathrm{fut}}$ (normalised), the ICL forecast behaves like $\hat y \approx (1-\lambda)\hat y_{0} + \lambda\,\overline{x^{\mathrm{fut}}}_k$, with $\lambda$ increasing in the examples' similarity to the query. The error of the template mean has a shared-bias term (does the example season match the query's?) and an idiosyncratic-variance term $\propto \sigma^2_{\text{idio}}/k$. Predictions: (i) when example futures are clean and alike (own earlier years of national load, Rossmann Christmas) the curve saturates at $k=1$–3; (ii) when they are noisy (finance volume, Walmart departments) small $k$ can be *worse* than zero-shot and the curve keeps improving to $k\ge 8$; (iii) the $k$ at which ICL overtakes zero-shot grows with the dispersion of the normalised example futures. Observed: ENTSO-e flat after 3; finance worse at $k=1$–3, par at 4, best at 12; Walmart flat to 2, improving to 10.
Source: k-curves in Walmart §4g, Rossmann §4e, energy §4d, econ §4d, finance §4e.

### R12 — FINAL (code fact). Prediction-length and context truncation rules.
`prediction_length` is resolved from `query_exog_future` length → `query_target_future` length → explicit argument (`pipeline._resolve_prediction_length`, `model._resolve_prediction_length`); histories are truncated to the **last** `iamtime_config.context_length` steps (`pipeline._process_icl_inputs`). Consequence for experiments: a known-future covariate must have exactly $H$ future steps; any example or query history longer than `context_length` is silently cut from the left.

## 3. Open questions and conjectures

Q1. **What is the mechanism behind R9?** H9a/H9b/H9c are mutually distinguishable (E5). If H9a holds, "examples that teach a covariate → response rule" needs a different experimental design (teachers with events at positions *different* from the query's) and may then work; if H9b holds, it is a model/pipeline defect to fix in `_build_encoder_inputs` or the mask builders; if H9c, a covariate-scaling convention is needed.

Q2. **Is the redundancy principle (R2) monotone in $L$, and where is the crossover?** Conjecture: $g(L)$ crosses zero at $L \approx$ one season for stationary seasonal series and never for series with a genuine regime in the horizon. (E3)

Q3. **Can examples carry information the history cannot, beyond seasonality?** Regime examples (series that went through a break the query is about to experience) are untested. Conjecture: they help iff the break is positionally aligned in the example futures (follows from R1 + H9a). (E8)

Q4. **Why do structural selectors beat similarity selectors (R3)?** Conjecture: z-normalised shape distance on the context matches noise when the context is short or the series noisy (GVAR inflation: analogues *hurt*, 1.57 vs 1.28; GDP cold start with 8 quarters: no gain), whereas a hierarchy encodes the shared future (same calendar, same product) directly. Test: the gain from similarity selection should increase with the signal-to-noise ratio of the context. (E4)

Q5. **Is the inverted-U in correlation for multivariate input real?** Gains appear for $\rho \in [0.5, 0.9]$ (Walmart triples, ETT HUFL/MUFL) and losses for $\rho \approx 1$ (Rossmann) and $\rho \approx 0$ (ETT OT). (E9)

Q6. **Does R10 occur in practice with the public checkpoint**, and does `use_arcsinh` bound it? (E7)

Q7. **How much of the covariate gain (R4) is the calendar vs. the event magnitude?** In finance, the earnings calendar alone gives most of the gain and past-only surprise history adds nothing; in Rossmann the promotion flag is binary. Conjecture: the model uses known-future covariates as *timing* information, and magnitude only through the context's own covariate → target relation (consistent with R6's shrinkage). (E10)

Q8. **Conservative extrapolation (R6): is the shrinkage a function of the covariate's normalised value?** Conjecture: the under-prediction ratio depends on how far the future covariate value lies outside the range of the history's values in normalised units, not on the raw multiple. (E11)

## 4. Rejected approaches and why

X1. **k-means (whole-history shape) neighbours as the selector.** No better than random series from other clusters (Walmart 0.992 vs 0.958; both vs 1.026). Shape over two years does not predict the shape of the specific season being forecast. Superseded by season-matched and sibling selection.

X2. **The query's own past alone as the single example** when the context already spans a season. Walmart $L=52$: 1.019 vs 1.026 (n.s.); Rossmann year-round: worse (0.784 vs 0.713). It duplicates information already in the context (R2).

X3. **Similarity analogues on noisy, mean-reverting series.** GVAR inflation: 5 analogues 1.573, 10 analogues 1.488, random windows 1.400, zero-shot 1.282. Matching the context's shape matches noise and the selected futures mislead (R1 makes this harmful rather than neutral).

X4. **Season-matched neighbours from arbitrary departments for cold start.** Walmart 12-week: mean 1.545 vs 1.329 zero-shot (median improves, mean worse): a few badly matched series dominate. Siblings (same department) are the safe choice (1.059).

X5. **Covariates inside examples** (until R9 is resolved). Kills the query's covariate response in the one test; all later notebooks avoid it.

X6. **Multivariate joint input as a headline capability.** R5: no dependable gain; the honest framing is "robust to joint input".

X7. **Past-only macro/market covariates as a selling point.** R4: GVAR commodity prices and finance market/macro series add nothing on top of the target's history and calendars.

X8. **Comparing ICL with a short context against zero-shot with a long one and calling the loss a failure.** Different question. The fair reference is zero-shot from the *same* context; the long-context zero-shot is reported as a ceiling that shows when examples are not needed (R2).

X9. **Pooled fev-style MASE for the demos.** Kept per-series MASE with mean, median and win rate, because the demos need a number per panel; pooled MASE is used only when comparing to the fev-bench leaderboard. (Not a rejection of the metric, a scoping decision.)

X10. **Daily returns as the finance target.** 0.773 vs 0.769 for a zero forecast: a martingale target shows nothing about any forecaster. Volume and realised volatility are the targets (R7).

## 5. What to test next

Each experiment: hypothesis → what to vary → confirming vs. refuting outcome → starting point. The notebooks hold runnable cells; the first step of every experiment is to extract the cell into `research/exp_<id>.py` so it runs headless and writes a CSV of per-series scores (the scorecard helper `scorecard()` and `plot_ladder()` live in every notebook's helper cell). Use the same seeds as the notebooks (`np.random.default_rng(0)` / `(1)`) so that baseline rows reproduce the published numbers before anything is varied. Record every run in `research/FINDINGS.md`.

### Validation of FINAL results

**E1 — Reproduce the reference rows (checks the prototype against this document).**
Hypothesis: the scorecard rows quoted in R1–R7 are reproducible to ±0.01 mean MASE on the same seeds and checkpoint.
Vary: nothing; run Walmart §1b/§2b/§3a/§4f, Rossmann §1b/§3a/§4c, energy §1b/§3a/§4c, econ §1b/§4c, finance §1b/§3a/§4c.
Confirms: all means within ±0.01 and all CI signs unchanged. Refutes: any row off by > 0.02 or a CI changing sign → the number in this document is wrong or the environment differs (log torch/numpy versions, dtype, device).
Start: each notebook's cell; `notebooks/iamtime_forecasting_findings.md` has the expected values.

**E2 — Graded shuffling (validates R1 and its magnitude).**
Hypothesis: error increases monotonically with the fraction $\phi$ of examples whose futures are swapped.
Vary: $\phi \in \{0, 0.2, 0.4, 0.6, 0.8, 1\}$ on the Walmart siblings set ($k=5$) and ENTSO-e own-years set ($k=3$ + 2); also swap futures with a *time shift* (same series, future offset by $H/2$) as a second control.
Confirms: monotone increase with $\phi$; the shifted-future control also degrades. Refutes: a flat curve up to $\phi=0.8$ followed by a jump (would suggest the model keys on a single example, e.g. the first) or no degradation under time-shift (would mean the model matches only the *level* of the futures).
Start: Walmart §4f `make_shuffled_example_input`; energy §4c control variant.

**E3 — Context-length sweep (validates R2; answers Q2).**
Hypothesis: $g(L)$ is non-increasing in $L$ and reaches ≈ 0 near one season.
Vary: $L \in \{8, 12, 26, 39, 52, 78, 104\}$ weeks (Walmart, siblings, $L_e = L$); $L \in \{14, 28, 56, 112, 224, 364\}$ days (ENTSO-e, own 3 years; Rossmann year-round and Christmas separately).
Confirms: monotone decrease of $g$ with the zero crossing within $\pm 25\%$ of one season; the Christmas series keeps $g>0$ at all $L<364$. Refutes: $g$ non-monotone or still > 5 % at $L$ = 2 seasons.
Start: Walmart §4h (`COLD_CONTEXT`, `COLD_HISTORY`), energy §4e, Rossmann §4d (parametrise `COLD_CONTEXT`).

**E4 — Selector ladder with matched data budget (validates R3; probes Q4).**
Hypothesis: on a fixed set of 512 Walmart queries with $L=52$, the ordering siblings < season-matched < random < cluster ≈ own-only holds under reseeding, and the gain from similarity selection correlates with the context's signal-to-noise ratio.
Vary: 5 seeds of the 512-series sample; stratify by the context's seasonal strength (ratio of seasonal-naive to one-step-naive in-sample MAE).
Confirms: ordering stable across seeds (rank correlation > 0.8); similarity-based gains increase with seasonal strength. Refutes: ordering changes sign between seeds, or similarity selection helps most on the *noisiest* tercile.
Start: Walmart §4e–4f variants dict.

**E12 — Multivariate ≡ past-only covariates (validates the code fact in R5).**
Hypothesis: `predict_quantiles` on a `(1, 3, L)` array gives, for variate 0, exactly the output of the dict input `{"target": y0, "past_covariates": {"a": y1, "b": y2}}`.
Vary: 20 random triples, both input forms, same batch.
